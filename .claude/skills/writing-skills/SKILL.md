# 하네스 작성 규율 (.claude/ 와 docs 정본)

## 1. 어디에 둘 것인가 — 4가지 그릇

| 그릇                        | 용도                                                               | 로드 방식                                  |
| --------------------------- | ------------------------------------------------------------------ | ------------------------------------------ |
| **정본 docs/**              | 규약 본문(진실의 단일 출처). 예: `docs/api-conventions.md`         | 사람·스킬·`review-gate.sh` 가 참조         |
| **rule `.claude/rules/`**   | 특정 경로 작업 시 상시 적용되는 규칙. 예: `src/**/*.controller.ts` | frontmatter `paths` 글롭 매칭 시 자동 로드 |
| **skill `.claude/skills/`** | "언제·어떻게"의 명시 절차/워크플로 래퍼                            | `description` 트리거로 발동                |
| **agent `.claude/agents/`** | 격리된 역할(읽기전용 리뷰 등) + 모델 차등(판단=opus·실행=haiku)    | 명시 위임 시                               |

**핵심 원칙: 규약 본문은 정본 docs 에만 두고, 스킬·룰은 중복하지 말고 참조한다**
(`api-endpoint` 가 `docs/api-conventions.md` 를 참조하는 방식). 본문을 여러 곳에 복붙하면
동기화 지점이 생긴다 — 정본 한 곳만 고치면 되게 유지한다.

## 2. 작성 규칙

- **frontmatter** — `name`(kebab-case, 파일경로와 일치) + 한국어 `description`. description 에는
  **발동 트리거 문구**(사용자가 실제로 쓸 표현)와 **경계**(언제 다른 스킬을 쓰는지)를 넣는다.
  트리거가 모호하면 발동되지 않는다.
- **본문** — 한국어, 짧게, **실제 명령**(`pnpm ...`)을 포함. 정본·룰 본문을 중복하지 말고 링크.
- **출처** — superpowers 등 외부에서 각색한 스킬은 파일 끝에 `<!-- 출처 (MIT) -->` 주석.
- **검증** — 훅을 고쳤으면 `pnpm check:hooks`. 새 스킬은 **새 세션**에서 트리거 프롬프트로
  디스커버리되는지, 기존 스킬 description 과 트리거가 충돌하지 않는지 확인한다.

## 3. 템플릿 ↔ 파생 백포트 규율

이 레포는 **보일러플레이트**다. 실제 프로젝트는 여기서 파생되어 각자 진화하고, 파생 쪽에서 먼저
강화된 하네스를 **템플릿으로 역반영(back-port)** 하는 것이 유지보수의 기본 방향이다. 템플릿이
구버전에 머물면 다음 파생 프로젝트가 개선을 물려받지 못한다.

- **역반영 대상(스택 무관)** — 훅·`lib.sh` 헬퍼·가드/게이트 스크립트, 스킬·룰의 절차와 규율,
  CI·공급망 설정. 파생에서 검증된 것만 가져온다.
- **제외(프로젝트 고유)** — 도메인 taxonomy 룰, 배포 파이프라인·인프라 잡, 앱별 env·시크릿,
  ADR 번호 참조, 모노레포 경로(`apps/*`·`packages/*`)와 워크스페이스 필터. 이식할 때
  **경로·모듈명·명령 리터럴을 템플릿 구조(`src/`·`test/`·`scripts/`)로 치환**한다.
- **분기 충돌** — 파생이 _되돌린_ 통제(예: 더 단순한 가드)는 자동으로 따라가지 않는다.
  보일러플레이트는 통제가 강한 편이 안전하므로, 약화되는 변경은 근거를 확인하고 결정한다.
- **검증** — 이식 후 `pnpm check:hooks`·`pnpm check:migrations`·`pnpm check:api-tests`·`pnpm test:cov`
  를 돌리고, 훅은 `bash -n` 문법 검사까지 한다.

변경 전 자문: ① 이건 스택 무관인가? ② 프로젝트 고유 리터럴을 치환했는가? ③ 정본을 중복하진 않았는가?
