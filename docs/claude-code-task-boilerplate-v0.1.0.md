# [작업 지시서] 보일러플레이트 v0.1.0 최초 배포

당신(Claude Code)은 이 레포지토리에서 보일러플레이트의 최초 버전 `v0.1.0`을 배포하는 작업을 수행한다.
아래 명세에 따라 작업하고, 마지막 **완료 기준**을 스스로 검증한 뒤 결과를 보고한다.

---

## 컨텍스트 / 전제

- 최초 배포 버전은 `v0.1.0`이다. (구조/API가 변경될 수 있는 초기 버전 가정)
- 시맨틱 버저닝을 따른다: MAJOR(호환성 깨짐) / MINOR(기능 추가) / PATCH(버그 수정).
- 커밋·PR 메시지는 Conventional Commits 컨벤션을 따른다 (`feat:`, `fix:`, `chore:`, `docs:` 등).
- 이 작업은 여러 레포지토리에 동일하게 반복 적용된다. 레포마다 스택이 다를 수 있으니, **먼저 레포를 스캔해 스택을 파악한 뒤** 그에 맞게 처리한다.

---

## 작업 절차

### STEP 1. 레포 분석

- 루트의 메타파일을 탐지해 스택과 버전 메타파일 위치를 파악한다.
  - Node → `package.json`
  - Python → `pyproject.toml` / `setup.cfg`
  - 그 외 → 해당 언어/도구의 버전 메타파일
- 기존 README, CI 설정, 디렉터리 구조를 읽고 보일러플레이트의 목적/범위를 요약한다.

### STEP 2. 버전 정보 반영

- 버전 메타파일의 `version` 필드를 `0.1.0`으로 설정한다.
- `CHANGELOG.md`를 생성(또는 갱신)하고 첫 항목을 추가한다.
  - 형식: `## [0.1.0] - <오늘 날짜>` + `### Added` 아래 주요 포함 항목.
  - 아래 "CHANGELOG 템플릿"을 사용한다.

### STEP 3. 문서화

- README(없으면 생성)에 다음을 명시한다:
  - 목적과 범위 / 포함·제외 항목 / 로컬 실행 방법 / 디렉터리 구조 요약.
- 브랜치 전략·커밋 컨벤션·버전 규칙을 README 또는 `CONTRIBUTING.md`에 명시한다.
- (해당 시) `.github/PULL_REQUEST_TEMPLATE.md`를 생성한다. 아래 "PR 템플릿" 사용.

### STEP 4. 커밋 & PR

- 변경 사항을 작업 브랜치에서 커밋한다.
  - 커밋 메시지 예: `chore: setup initial release v0.1.0`
- main으로의 PR을 생성하고, PR 본문은 아래 "PR 설명 템플릿"을 채워 작성한다.
- 결정 사항(폴더 구조·네이밍·라이브러리 선택 이유)을 PR 본문에 명시한다.

### STEP 5. 태그 & 릴리스 (사람 승인/머지 이후 단계)

> 아래는 main 머지가 완료된 후 수행한다. 머지 권한이 없거나 머지 전이면 **명령어만 보고**하고 직접 실행하지 않는다.

```bash
git checkout main
git pull
git tag -a v0.1.0 -m "Initial release v0.1.0"
git push origin v0.1.0
```

- 태그 푸시 후 GitHub/GitLab Release를 생성하고, 릴리스 노트는 CHANGELOG 0.1.0 항목과 일치시킨다.

### STEP 6. 브랜치 보호 규칙

> 레포 설정 변경 권한이 필요하므로, 권한이 없으면 **권장 설정을 보고**한다.

- main 직접 푸시 금지 / PR 필수 / 리뷰 승인 1개 이상 / CI 통과 필수.

---

## 제약 사항

- 위험한 작업(force push, 브랜치 삭제, 시크릿 노출)은 수행하지 않는다.
- main에 직접 푸시하지 않는다. 반드시 PR을 경유한다.
- STEP 5~6처럼 권한이 필요한 작업은, 권한이 없으면 실행 대신 수행할 명령/설정을 보고한다.
- 레포에 이미 버전/태그/CHANGELOG가 존재하면 덮어쓰지 말고 현황을 보고한 뒤 지시를 기다린다.

---

## 완료 기준 (작업 종료 전 스스로 검증)

다음을 모두 확인하고 결과를 보고한다.

1. 버전 메타파일의 `version` == `0.1.0`
2. `CHANGELOG.md`에 `0.1.0` 항목 존재, 날짜·내용 채워짐
3. README에 목적/실행법/구조 및 브랜치·커밋·버전 규칙 명시됨
4. main 대상 PR 생성됨, PR 본문 템플릿이 채워짐, 제목이 컨벤션을 따름
5. CI(lint/build/test)가 정의되어 있다면 통과 상태
6. (권한 있을 시) `v0.1.0` 태그 푸시 및 Release 등록 / 없으면 명령어 보고
7. (권한 있을 시) 브랜치 보호 규칙 적용 / 없으면 권장 설정 보고

## 보고 형식

작업 종료 시 아래를 출력한다.

- 감지된 스택 및 버전 메타파일 경로
- 변경/생성한 파일 목록
- 생성한 PR 링크(또는 브랜치명)
- 위 완료 기준 1~7에 대한 충족 여부 표
- 권한 부족 등으로 수행하지 못해 사람이 처리해야 할 항목
